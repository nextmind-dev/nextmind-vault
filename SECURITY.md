# Security Policy

## Current status

NextMind Vault is in development and is not available for download. The application code is not published in this repository and has not yet completed an independent security audit.

This repository currently contains public product documentation only. Security reports may still concern published documentation, future release artifacts, project infrastructure, or statements that could create unsafe expectations.

## Reporting a vulnerability

Please report suspected vulnerabilities privately. Do not publish exploit details, recovery material, credentials, personal data, or sensitive diagnostic information in a public issue.

Preferred reporting path:

1. Use GitHub's private vulnerability reporting feature for this repository when it is available.
2. If private reporting is unavailable, contact the repository owner, **Nico (`nextmind-dev`)**, through GitHub and request a private reporting channel. Do not include sensitive details in the initial public contact.

Include, where possible:

- the affected version or artifact;
- a clear description and reproducible steps using synthetic data;
- expected and observed behavior;
- impact and preconditions;
- suggested remediation, if known.

## Response principles

Reports will be assessed against the documented threat model and supported versions. Receipt of a report is not a promise of a specific timeline, but good-faith reports will be handled responsibly and with an effort to minimize unnecessary disclosure.

## Safe research

Do not test against other people's data or systems, use real credentials, degrade services, or attempt social engineering. Research should use locally controlled environments and synthetic data.

This policy does not create a bug bounty or authorize activity that would otherwise be unlawful.
